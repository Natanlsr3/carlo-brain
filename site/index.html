A Jarvis for Claude Code.

A personal agentic system: a structured memory loaded only where it matters, specialist subagents with ready-made prompts, agents that review and improve it, and connectors to your tools. All in a folder of Markdown you own. Built for Claude Code, and plugged into Codex CLI, Gemini CLI or any other LLM with one command each (Claude Code stays the most complete).

A Jarvis, not a memory plugin

Memory is one piece. This is the whole assistant.

A memory plugin remembers context, and a good one does it well. Carlo Brain does not try to out-remember it. It builds the system around the memory, in Markdown you can read and edit.

A memory map, loaded lazily

A short map of who you are and where each project lives. The boot hook adds the recent past, capped at 9,000 characters. The rest is read on demand, branch by branch.

Subagents with ready prompts

Researcher, reviewer, cto, reader and more. Each is a Markdown file with a role, minimal tools and rules. The main assistant delegates instead of filling its own context.

Review and proactive agents

A reviewer that runs on its own after code changes. A proactive layer for mail, chats and todo. A weekly loop that audits your setup and proposes changes, applied by code with backup and undo.

Connectors

Apple apps, WhatsApp, Google, Notion, Slack, the browser (Playwright set up in one command, Claude in Chrome), web research, and routing to other models through OpenRouter, with Claude as fallback.

Codex, Gemini or any LLM

carlo connect codex or carlo connect gemini gives them the same rules, boot context, guards and agents, and removes them cleanly. carlo context --copy makes one paste-ready prompt for any other chat. Fewer hooks than Claude Code, said plainly in the docs.

Safeguards

Drafts first, then go. Secrets never opened. Sends with keys or card numbers blocked. Every send audited. A seat belt, not a sandbox.

Watchdog and search

A watchdog tells your next session which job or connector broke and relaunches a missed job. carlo search looks through your vault, folders, Notes, Messages and Mail before the assistant asks you. It also reads PDFs, Office files and mail bodies, and repairs what is safe to repair on its own.

The problem

Claude Code is brilliant and forgets everything.

Every session starts from zero. You re-explain who you are, what you are working on, and which rules it must follow. And it waits to be asked, while the things that hurt are the ones nobody asks about.

  • Amnesia. The same context, every morning.
  • Passivity. A reply you owe. A schedule that never reached your calendar.
  • Fragility. A secret printed in a transcript. A message sent that you never read. A self-editing agent that cannot go back.
  • Bloat. One giant instructions file, slow, costly and half stale.
A day with it

It works while you do not.

Morning briefing, one question

Five points, under 200 words, ending with a single closed question. Built from your messages, mail and todo without any model call.

Drafts first, then "go"

It prepares the reply and shows it. You type go and exactly that text is sent. Change a word and it comes back to you. Messages with keys or card numbers are blocked before they leave.

Memory across sessions

Each session ends with a log entry: done, decided, next. If the assistant forgets, a hook writes one. Corrections you give become rules, with a diff you approve.

A weekly loop that improves it

A scout looks outside, an improver audits your setup. They only propose. Code decides: safe edits are applied with a backup and checks, system prompt changes wait for your eyes, anything near secrets is refused. Undo with one command.

Night work

Queue a multi-step task. When it is dark, you are home and the laptop is plugged in, it works one step at a time with every send tool denied. Morning: one line per task.

Modules

Take what you need. Remove it cleanly.

The core is always installed. Every module is added and removed with one command, and removal restores your settings.

System prompt, a short map of you, session log, corrections log, starter skills. An Obsidian vault plus one managed block in your CLAUDE.md.

tested

memory

Boot context at session start, hard capped. Automatic log entries, compaction summary, facts to validate, session quality score.

tested

security

Blocks secret reads and sends that contain secrets. Hash-chained audit of every send. Loop and alignment guardrails.

tested

sync

Commits your vault at session start and end, optional private remote and server copy. Never force-pushes.

beta

connectors

Apple apps, WhatsApp, Google, Notion, Slack, browser, web research, phone control, a personal server, a vault MCP endpoint.

beta

self-improve

Weekly scout and improver, tiered apply with backup and restore, undo, a personal bench, a scheduler that catches up after sleep.

beta

night

Queue of multi-step tasks, optional marathon, judged on a STATUS line, morning report.

beta

agents-skills

Researcher, cto, reviewer, reader, listener, improver, video-quiz agents. Writer, docs, explainer skills. Never overwrites yours.

beta

review-loop

After a session changes code, the reviewer agent is asked to check the diff before "done". Once per diff, no loops.

beta

Watchdog for scheduled jobs and connectors. Reports only what broke, relaunches a missed job once.

beta

Read-only search across your vault, folders, Notes, Messages and Mail, with a deny list for secrets.

beta

The same brain in Codex or Gemini CLI (instructions, boot hook, guards, agents) with one command, and a paste-ready prompt for any other LLM.

Three things, one convention.

A vault for memory, hooks for housekeeping, scheduled jobs for what happens between sessions. Modules talk to the next session through a folder of small files.

The one convention: any script can add a section to the next session by writing a Markdown file to boot.d/. A first line <!-- once --> deletes it after it is shown. No module imports another.
Built to be trusted

A seat belt, and honest about its limits.

Autonomy is only useful if the mistakes it makes are cheap. The defaults are conservative, and the code, not the model, draws the lines.

  • Read freely, write on your go. Show the text, send on go.
  • Secrets are never opened. Keys live in a mode 600 folder and are passed by path.
  • Unattended never sends. Every send, create and update tool is denied in night and weekly jobs.
  • Reversible. Settings edits are backed up and tagged. Automatic changes are archived and undoable.
  • Your subscription, not a surprise bill. Background calls strip API key variables.
  • Not a sandbox. It is a pattern-matching seat belt. The docs say where it stops.
Install

Three commands.

You need macOS or Linux, Claude Code, Python 3.9+, git, and Obsidian if you want a comfortable window on your vault. The installer asks for a vault folder, a name for your assistant and your first name.

Then fill in 00_System/MAP.md with who you are and what you work on. Five minutes, and the most valuable ones. How, in 10 minutes.

proactive and connectors need a source connected first (WhatsApp, Apple Mail, a todo export), so they are not in the snippet. Connect your sources.

Everything it changes is listed in the install guide, and carlo uninstall puts it back.

# 1. get it
git clone https://github.com/Natanlsr3/carlo-brain
cd carlo-brain

# 2. install the core, memory and security
./install.sh

# 3. add modules that need no setup, then check
carlo add agents-skills search review-loop health
carlo doctor

Full guide: docs/02-install.md. Connect your sources: docs/03-connect-your-sources.md.

Your first 10 minutes

Fill one file, then start claude.

Without a map the first boot is empty. Five minutes on one file fixes that.

Fill in your map

Open 00_System/MAP.md in your vault (default ~/carlo-vault): who you are, your three projects, where their files are.

Start claude and read the first message

A one-sentence "Ready" that recalls what it knows. Day one has no history, so it is short. Nothing there? Run carlo doctor.

Try three things

After one small task, restart and type What did we do last session? Correct it once (Answer in two lines maximum from now on. Remember this.), say yes to the diff and watch a line land in CORRECTIONS.md. Then run carlo search "pricing" in a terminal.

Add the next module, knowing what it needs

Nothing needed: agents-skills, search, review-loop, health. Git: sync. A source connected first: proactive, connectors. A long-lived login: self-improve, night.

# a 6-line MAP.md
**Who**: Sam, product designer in Lyon. Short answers, works in the evening.
**Active projects**:
- Website redesign: pricing page. Entry file: `10_Projects/website/website.md`.
- Freelance clients: two invoices to chase. Entry file: `10_Projects/clients/clients.md`.
- Spanish course: 20 min a day. Entry file: `10_Projects/spanish/spanish.md`.
**Where to look for more**: todo in Reminders, contacts in Contacts.

Honest status

Beta 0.1.

The core modules are tested end to end in a temporary home directory. The ones that read your mail and chats, or run while you sleep, are tested against simulated sources and a fake claude.

Apple's private database layouts can change with a macOS update, and the WhatsApp bridge is an unofficial client. Each module README has a Known limits section, and the docs cover costs and what uses your subscription. Run unattended jobs by hand first.
