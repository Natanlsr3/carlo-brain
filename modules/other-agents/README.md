# other-agents

Use the same second brain with **OpenAI Codex CLI**, **Google Gemini CLI**, or any chat or agent that can take a pasted prompt. Claude Code stays the most complete host (more hooks, real subagents, scheduled jobs); this module gives the others what their documented extension points allow, and says plainly where they stop.

Status: **beta**. File formats and command lines are covered by tests with fake tools; nothing here was run against a real `codex` or `gemini` binary.

## Commands

```text
carlo connect codex            carlo connect gemini
  --status                       is it connected, hook count, binary on PATH
  --remove                       take out our block, hooks, exported prompts (backups kept)
  --no-hooks  --no-agents        instructions block only / do not export agents and skills
  --mcp                          also register the Playwright MCP server (needs `carlo connect browser` first)
  --inline                       gemini only: copy the prompt and map into the file instead of @imports
carlo context [--copy] [--max N]   one paste-ready prompt for any LLM (default cap 24,000 characters)
carlo context --boot               only the boot context (what the Claude hook injects)
carlo context --refresh            regenerate the Codex block from the vault
carlo doctor                       shows the connected tools
```

`carlo connect` installs this module (and `memory`) the first time. `carlo remove other-agents` disconnects both tools first. `carlo context` works before the module is installed.

## What is written, where

Everything is tagged, backed up as `<file>.bak-carlo-<time>` before a change, idempotent (no change, no new backup), and removed by `--remove` without touching your own content.

- **Instructions block** in `~/.codex/AGENTS.md` (or `$CODEX_HOME/AGENTS.md`) or `~/.gemini/GEMINI.md`, between `carlo-brain:begin` and `end` markers. It carries the rules: who you are comes from the map, where the vault is, read on demand, log each session to `SESSION_LOG.md`, nothing sent without "go", never read secret files, `carlo search` before asking.
  - Gemini: the system prompt and map are `@file` imports (always fresh, no size limit).
  - Codex: no import syntax is documented, so the block holds a generated copy, capped (11 KB of system prompt, 4 KB of map, about 18 KB in all; Codex reads 32 KiB in total). It is regenerated by `carlo context --refresh` and at every session start by the hook (it applies from the next session, since the file is read before the hook runs).
- **Boot hook**: a SessionStart hook runs the memory module's `boot.py` unchanged. Both tools accept the same `hookSpecificOutput.additionalContext` output as Claude Code. If the hook did not run (Codex before you trust it), the block tells the agent to run `carlo context --boot` as its first action.
- **Guards**: a pre-tool hook runs `block_secret_reads.py` and `send_guard.py tool` from the `security` module through `guard_adapter.py`, which renames the tool and its arguments to the shape those scripts read. Exit 2 with a reason on stderr blocks the call in both tools. Needs the `security` module; without it only the boot hook is wired.
- **Agents and skills** (from `agents-skills`): Codex gets one skill per agent or skill in `~/.agents/skills/carlo-<name>/`; Gemini gets `~/.gemini/commands/carlo/<name>.toml`, used as `/carlo:cto <task>`. A file or folder of the same name that is not ours is never overwritten or removed.
- **MCP** (`--mcp`): only Playwright, only if you ran `carlo connect browser` (its version pin is reused): `codex mcp add playwright -- npx @playwright/mcp@V` or `gemini mcp add -s user playwright npx @playwright/mcp@V`.

## What works per tool

- **Codex CLI**: instructions yes (inline copy), boot context yes after you trust the hook once (`/hooks` in Codex), secret-read and send guards yes on shell commands and `apply_patch`, agents as skills, Playwright MCP yes (removal of the MCP entry is manual: no remove command is documented).
- **Gemini CLI**: instructions yes (imports), boot context yes, secret-read guard yes on shell and file tools, send guard on shell commands only (MCP tool names in Gemini hooks are not documented, so MCP sends are unguarded), agents as `/carlo:<name>` commands, Playwright MCP yes.
- **Any other LLM**: `carlo context --copy` gives the system prompt, map, recent sessions and briefing in one capped text for the first message. No hooks, no guards, no log writing unless that tool can write files. Re-run it per chat.

## Limits, honestly

- **Not tested against the real tools.** The hook JSON, TOML and command lines follow the vendors' docs (below); a version change can break them. `--status` and `carlo doctor` only check our files.
- **Codex hooks need your trust.** Codex records trust per hook hash and skips unreviewed hooks. After `carlo connect codex`, open Codex and run `/hooks`. Each time we change a hook, trust it again.
- **Fewer guards than Claude Code.** Not wired: prompt-time guards (the `send anyway` override, alignment reminders), the audit chain, the "tests before stop" check. The audit log therefore does not record sends made from Codex or Gemini.
- **Codex `AGENTS.override.md`**: if it exists and is not empty, Codex ignores `AGENTS.md`; connect warns.
- **Gemini `settings.json`** is rewritten as plain JSON (comments, if you had any, are lost; a backup is kept). A file that does not parse stops the command with nothing changed.
- **Exported agents lose Claude specifics**: tool lists, model hints and delegation to other agents; a preface says so. The `explainer` skill keeps its reference file in Codex but not in Gemini commands.
- **Vault MCP** is not registered: its token and transport setup differ per tool and are not verified here. Use the `claude` route, or add it by hand.
- Session log writing, corrections and `carlo search` are instructions to the model, not hooks. A model can forget; there is no automatic `[auto]` log entry from these tools.

## Facts this is built on (checked 2026-11-23)

Codex: global file `~/.codex/AGENTS.md`, `CODEX_HOME` override, `AGENTS.override.md` first, `project_doc_max_bytes` 32 KiB, no `@import` mentioned (https://learn.chatgpt.com/docs/agent-configuration/agents-md). Hooks in `$CODEX_HOME/hooks.json` or `[hooks]` in `config.toml`, events SessionStart, PreToolUse, PostToolUse and more, stdout or `additionalContext` becomes developer context, `permissionDecision: "deny"` or exit 2 blocks, shell tool is `Bash` with `tool_input.command`, edits are `apply_patch`, MCP tools `mcp__server__tool`, timeout in seconds, unreviewed hooks skipped until trusted (https://learn.chatgpt.com/docs/hooks). MCP: `[mcp_servers.<name>]` in `config.toml`, `codex mcp add/list/login` (https://learn.chatgpt.com/docs/extend/mcp?surface=cli). Skills in `$HOME/.agents/skills/<name>/SKILL.md` with `name` and `description` (https://learn.chatgpt.com/docs/build-skills.md).

Gemini: `~/.gemini/GEMINI.md`, `@file` imports with relative or absolute paths, `context.fileName` configurable (https://raw.githubusercontent.com/google-gemini/gemini-cli/main/docs/cli/gemini-md.md). Hooks in `~/.gemini/settings.json`, events SessionStart, BeforeTool and more, timeout in milliseconds, SessionStart `hookSpecificOutput.additionalContext`, BeforeTool exit 2 blocks with stderr as reason (https://raw.githubusercontent.com/google-gemini/gemini-cli/main/docs/hooks/index.md and `.../hooks/reference.md`). Tool names `run_shell_command`, `read_file`, `glob`, `grep_search`, `write_file`, `replace`... (https://raw.githubusercontent.com/google-gemini/gemini-cli/main/docs/reference/tools.md). MCP: `mcpServers` in `settings.json`, `gemini mcp add/remove/list` with `-s user` (https://raw.githubusercontent.com/google-gemini/gemini-cli/main/docs/tools/mcp-server.md). Custom commands: `~/.gemini/commands/<ns>/<name>.toml`, `prompt` and `description`, `{{args}}`, `@{}` and `!{}` injection (https://raw.githubusercontent.com/google-gemini/gemini-cli/main/docs/cli/custom-commands.md).
